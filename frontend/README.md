# Фронтенд Mountain & Sea Spa

React + TypeScript + Vite приложение для управляющего спа-объектом. Помогает контролировать остатки, видеть риски и принимать решения о закупках на основе расчётов mock API.

## Возможности

- Дашборд с KPI, предупреждениями и ближайшими заказами.
- Остатки с фильтрами, карточкой товара, партиями и движением с пагинацией.
- Предупреждения с уровнем риска, показателями и рекомендацией.
- Расчёт закупки с изменяемыми параметрами, предупреждениями и обоснованием: исходные данные, формулы и допущения.
- Список заказов на выбранный горизонт, план закупок и бюджет с разбивками и сравнением с предыдущим периодом.
- Динамика закупочных цен, себестоимость и маржинальность услуг, сценарий изменения цен.
- Чат с историей, примерами вопросов, таблицами, расчётами и кликабельными уточнениями.
- Выгрузка расчёта закупки, списка заказов и плана в JSON вместе с данными API.

## Стек

- React 19, TypeScript 6, Vite 8;
- React Router 7 и TanStack Query 5;
- CSS, Vitest, Prettier.

## Запуск

Frontend запускается как самостоятельный проект. Для работы с данными отдельно запустите backend API. По умолчанию frontend ожидает его на `http://localhost:8000`.

### Локально

Нужны Node.js 24 и npm. Выполните команды из директории `spa-front/frontend`:

```bash
npm ci
npm run dev
```

Откройте <http://localhost:5173>. Dev-сервер передаёт запросы `/api` отдельно запущенному backend.

### Через Docker

Из директории `spa-front/frontend` выполните команды в среде с доступным Docker (на Windows — через WSL):

```bash
docker build -t spa-frontend .
docker run --rm -p 5173:5173 -e VITE_API_URL=http://localhost:8000 spa-frontend
```

Откройте <http://localhost:5173>. В этом примере браузер обращается к отдельно запущенному API по `http://localhost:8000`. Если адрес API другой, замените значение `VITE_API_URL` в команде запуска.

## Настройка API

Адрес API не задан в компонентах. При пустом `VITE_API_URL` запросы на `/api` идут через прокси dev-сервера Vite; его цель задаётся переменной `VITE_API_PROXY_TARGET` (по умолчанию `http://localhost:8000`). Если backend доступен по другому адресу, укажите `VITE_API_PROXY_TARGET` в `spa-front/frontend/.env.local`. Для прямых запросов из браузера задайте `VITE_API_URL` как полный адрес API; для статической сборки укажите его до `npm run build`. Пример значений — в [`.env.example`](.env.example).

Переключатель объекта загружает варианты из `/api/meta` и передаёт выбранный объект в поддерживающие его запросы. Эндпоинты цен и экономики услуг не имеют фильтра по объекту, поэтому их показатели относятся ко всей сети SPA.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Локальный сервер Vite |
| `npm run build` | Проверка TypeScript и сборка в `dist/` |
| `npm run preview` | Просмотр собранной версии; для запросов к API нужен `VITE_API_URL` при сборке или внешний прокси |
| `npm test` | Тесты Vitest |
| `npm run format` | Форматирование исходников Prettier |

## Архитектура

- `src/app` — маршруты, общий макет и выбор объекта;
- `src/pages` — экраны приложения;
- `src/shared/api.ts` — единый клиент запросов к mock API;
- `src/shared/types.ts` — типы ответов API;
- `src/shared/ui.tsx` — общие компоненты состояний, таблиц и обоснования расчётов;
- `src/shared/format.ts` и `src/shared/export.ts` — форматирование и выгрузка JSON.

TanStack Query хранит серверные данные и разделяет кеш по параметрам запроса. Показатели закупок и бюджета frontend не рассчитывает: он отображает значения из API. Для запросов предусмотрены состояния загрузки, ошибки и пустого результата. Тесты API-клиента находятся в `src/shared/api.test.ts`.

## Данные демонстрации

Mock API использует синтетические данные и хранит историю чата в памяти. После перезапуска backend история очищается, а набор данных строится заново на текущую дату. Интерфейс показывает рекомендации, но не размещает заказы автоматически.
